# D_validate 更新模型自身状态覆盖修正

2026-10-19，在正式选择/验证结果产生前核对原计划，发现冻结 v4 的自由生成与自身状态覆盖不同。原计划 6.1/6.2 固定 D_validate 为 `[512,1024)`、512题；9.4要求两个更新模型在该集合各自重新生成并测量自身状态，没有授权状态子抽样。

`run_state_calibration_study.py:553` 对入围臂生成全部512题，但第556行的更新模型自身状态采集和第394行的分析全集均为 `[512,640)`、128题。原 protocol 的 `formal.diag=128` 对应 C_diag，不能代替 D_validate 的512题要求。冻结源码和质量草案记录了该子集，也不意味着原要求已经满足。

保留原 v4、18份测量源码、5份质量分析源码/文档及全部原始结果。原128题继续作为已声明的固定子集，不将其显著性或完整性冒充全512题证据。补足阶段使用独立、在验证结果出现前封存的计划和源码副本，数据写入独立 scratch 目录，锁和活跃PID控制放在当前节点 RAID。

只有原 P3 门控实际触发 P4、产生两种更新校准时，才要求这项更新模型补充。若P4明确未触发，报告不适用；缺少、损坏、等待中的状态不能当作不适用或完成。

补充直接使用正式 D_validate 保存的 M_NT/M_ST 各512条无observer生成轨迹；不重新拟合，不调整方法、参数、题目、上限或质量阈值。使用冻结的 StudyDriver.replay 和 StateCollector，在各模型自己的固定轨迹上采集全部有效decode位置，核验完整argmax、48层、T−1、EOS/empty及driver/calibration/位置mask身份。原128份归档只有在轨迹及全部身份逐项一致后才能复用，并保留复制来源；不一致时不得假装已覆盖。

分析使用明确的512题全集、原定10000次paired prompt bootstrap和seed，保留token主分析与prompt等权敏感性。统计完成不要求得到正向结果。最终正向链的validation自身状态条件由完整512题主证据决定，不能因128子集正向就通过，也不能因该子集区间未通过而忽略全512题。其它P0/P3/C_diag、匹配拟合、强基线、双评分质量和请求成本条件保持原已封存规则。

原core的P5 complete只证明其既有512生成/128状态流程结束。若P4触发，整项交付还须完成新512覆盖、原始归档校验、两模型各自状态/配对区间、额外离线成本和中文报告。补充必须在实际core模型退出后串行执行，跨allocation使用独立启动证据和同样的PID/调度/来源核验，不并发加载第二个模型。

当前修正正在实现与审阅；本说明本身不证明补充计划已经封存，或512题已经采集完成。以实际计划、源码归档、提交文件、分析和交付报告为准。
